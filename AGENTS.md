# AGENTS.md

King's Commission (working title) is a browser game: King's Bounty (1990) rebuilt with modern tech and the charm of Heroes of Might and Magic 2. Read `docs/BRIEF.md` for the design and every decision made so far, `docs/PLAN.md` for the structure, testing and milestones, `docs/WORLD.md` for the story and the world, and `docs/BALANCE.md` for the power budget: what a proper challenge is, the levers, and how the sims measure it.

## Working with Artur

- Reply fast and keep it short. Before any step that will take more than a minute or two, post a one-line status. Never go silent.
- Show, don't tell. Open the game in the browser side panel and screenshot it. Use a mermaid diagram for flows.
- Build in small, visible steps. Check in before any big build or long design deep-dive.
- No image-generation models for art. The troops and the hero are Battle for Wesnoth's units (GPL-2.0-or-later and CC BY-SA 4.0, credited file by file in `public/assets/CREDITS.md`); everything else is drawn in code. The game is GPL-2.0-or-later (`LICENSE`).
- **Build locally, from issues** (Artur, 29 Sep). An issue says what and why. A session on this Mac builds it on a branch in its own worktree and runs the checks here: `npm run typecheck`, `npm run test:fast`, the tests it touched, `npm run e2e` and the playtest (`node scripts/playtest.mjs`) for visible changes, and `npm run visual` when it changes a frozen scene (baselines can be approved here, as this is a Mac). It looks at its screenshots. Then it opens a PR that says `Fixes #N` (or `Part of #N`), and squash-merges it itself once CI's three PR jobs are green. Never push to main. The issue and its PR are the record of what was done and how.
- **Ship fast** (Artur, 28 Sep: "I want to just play this, and I'll tell you if something is not working"). Ship small slices through pull requests; the session merges its own PR once CI is green, and never pushes to main. Don't hold work back for long docs. Follow `.github/skills/kings-commission-ship/SKILL.md`.
- **Issues.** Bugs and features live in [GitHub Issues](https://github.com/arturcrmbot/kings-commission/issues), with labels for the kind (`bug`, `feature`, `playtest`), the area (`battle`, `ai`, `content`, `ux`, `art`, `audio`, `balance`, `ci`) and the status (`in progress`, `next`, `later`, `parked`). Close issues from PRs (`Fixes #12`).
- **Models** (Artur, 29 Sep). Sessions and their helpers run on Claude Opus 5.5, at max reasoning effort, with long context (`claude-opus-5.5`, `max`, `long_context`).

## Architecture

- `src/content/`: typed game data. Provinces (land, places, decor), troops, spells, backgrounds, skills, perks and artifacts.
- `src/rules/`: the game rules in plain TypeScript, with no Three.js, DOM or timers. Every change is `(state, action) → { state, events }`, and dice come from the seed in the state. The rules own the logical map (`map/`: 8 px walk grid, pathfinding, movement, fog). They write the cards' words too, and any list in them goes through `listed` in `state.ts` ("3 Knights, 2 Archers and 1 Swordsman"). Tested with Vitest.
- **Extending the game.** Most additions are data:
  - Land: a province's forests (each with its share of pines), its regions painted their own way (`fields`, `heath`, `downs`), crags, a river with a bridge wherever a road crosses it (or a ford, where `fords` says), roads and places are data in `src/content/`; `rules/map/model.ts` builds the walk grid from them and `render/terrain.ts` paints them.
  - Places: each kind of place is one module in `src/rules/places/` (a `PlaceKind`: its cards, arrival, own choices, payday, bot appetite), registered in `places/index.ts`. Towers, mines and mills show their `pages` when they have them, so a find is a choice written as content; so do castles and villages while a page holds (the old King's hunt hall, locked), and after a choice there they show their own recruit card (`PlaceKind.card`). A place that looks different once something happens to it (the hunt hall, opened) sends a `changed` event, and the map draws it anew (`refreshPlace` in `render/adventureScene.ts`).
  - Beasts (wild things with no wages that aren't villains: `isBeast` in `content/troops.ts`) can be tamed by a hero with `tames`: see `tameOffer` in `places/enemy.ts`. Troops who draw no wages but aren't wild, like the old King's huntsmen, say why on their card (`unpaid`).
  - Content choices: shrines, quests, parleys and events are content. They're pages of choices with `Needs` (conditions and costs, including `flag`/`notFlag`, `seen` (a place visited) and `notSpell`) and `Effects` (gold, treasure, stats, spells, troops, flags, reveal, xp, win, a new `place`, `reinforce` another enemy, `desert` this one, `travel` by a shortcut, `recruits` at a place (free, or with no payday restock, if the content says so), `rations` for the baggage (a payday's wages each)...), interpreted by `src/rules/effects/`, with story state in `state.flags`. A flag set by one place's spoils or choice can open a choice somewhere else: that is how choices come back later. A victory can ask a question too: its spoils name a page (`spoils.page`), and the victory card offers that page's choices (the grain cart's: whose grain is it now?). A choice the hero can't take shows greyed out (`needs`), naming only what he lacks (`lacksLabel`): the wrong sort of hero hears only that, and a story need he hasn't met says the choice's quiet `hint`, if it has one ("a song you don't know yet"). One with a `when` that doesn't hold isn't there at all, so a question only appears once there's something to ask about (Old Nan's, once the hall has been seen). Gear a choice asks for (`needs.artifact`) can't be sold at the armoury while that choice is still open (`wantedAt` in `rules/hero.ts`).
  - Relics (`RELICS` in `src/content/artifacts.ts`) carry a background's trick as a `Bonus` (charge, volley, forestWalk, casts, mapSpells, bribes, hires, tames), so any hero can pick one up.
  - The bounty: each commission's villain (and each generated one's template) has his `face`, the poster's `wanted` line, his `lastWords` (said on the field as his army is beaten, in a bubble and his `voice` from `content/troops.ts`, and quoted on the card) and what comes home (`homecoming`, with a picture in `returned`). The poster's price is the hideout's `reward` (`bountyOf`); a choice that takes him for another price says `because`, and the WANTED poster comes back stamped PAID with it (`bountyCard` in `rules/heroSheet.ts`).
  - The court: what the King remembers (`memories`) and who would ride on with Aldric (`friends`) are each commission's data in `src/content/campaign.ts`, read from `state.flags` at court (`happened` in `rules/campaign.ts`: `true` for any value, anything else exactly, `false` for a flag spent). The people are `src/content/friends.ts`: each is offered as a boon, and once taken rides with him for good (`hero.friends`), his `Bonus` counted with the rest, and may bring troops into the next commission (`brings`).
  - The journal (J): the commission on its pinned poster, and the things heard on the road. What was heard is each commission's `heard` in `src/content/campaign.ts`: the words as someone said or wrote them, who, and the clues (story flags, a place `seen` or `used`) for when it was heard (a flag spent since still counts) and when it paid off, ticked. `heardOf` in `rules/campaign.ts` reads them, `journalCard` in `rules/heroSheet.ts` writes the page, and the card draws it as two pages (`Card.journal`). A new thread in the content can add its line there.
  - Sets (`SETS` in `artifacts.ts`, and each piece's `set`): every piece worn adds the set's `Bonus` (`wornSets` in `rules/hero.ts`). A piece's note says what its set does; a find says how many are worn. A new artifact's 16×16 picture goes in `src/render/artifactPictures.ts`.
  - Skills (`src/content/skills.ts`): each has three ranks, and each rank is the whole `Bonus` at that rank with its note, so Advanced and Expert add a trick to the number. Tricks that aren't battle fields are read where they happen: `offRoad` in `map/movement.ts`, `manaRide` in `stepAlong`, `shadow` in `map/roaming.ts` and `rules/dawn.ts`, `veterans` in `campaign.ts`, `volunteers`, `restock` and `rents` in `rules/dawn.ts` (paydays), `odds`, `cows` and `hiresGates` in `places/enemy.ts`. Perks (`PERKS`, same file) work the same way: `freeRecruits` in `places/dwelling.ts`, `carry` and `smells` in `rules/dawn.ts`, `interest` in `heroStats` (paid with the King's gold), `choices` in `drawOptions` and `boons` at court.
  - Battle: spells, statuses and troop abilities are data in `src/content/spells.ts` and `troops.ts`, and the battle engine reads them generically. Aldric fights too, as one troop per background (`hero` in `troops.ts`: his damage grows with his level); `heroFighter` in `rules/fight.ts` gives his numbers, and `createBattle` puts him behind the line from `BattleHero.unit`. Leaders (Aldric, villains, captains) are troops with the `leads` ability: they stand off the field (`REAR`), no blow, shot or spell can target them, they take a turn only with something to do in it, and a side is beaten when its troops (`onField`) are; `rides` lets one ride out to strike and back (`rideReach`), and `bard` gives one a bard's moves instead (pay, jeer, sing: `bribePrice`, with morale and luck per stack in `moraleOf` and `luckOf`). `battleEnd` gives the words the field and the card both use.
  - Captains (the enemy's named lieutenants, #15) are data too: a leader troop in a band's army (`rook` in `troops.ts`), with a `face` for the band's cards, the band's `lastWords` as he's taken, and a trick that is an ability (Rook's `marks`: his shots put `marked` on their target). Any villain's band can have one. On the map a band with a leader shows him, with its main troop at his heel.
  - Luck and morale: `Bonus.luck` and `Bonus.morale` are Aldric's gifts to his side, statuses add theirs (a bard's songs and jeers), and each troop's `people` (with the pairs in `FEUDS`, `troops.ts`) lowers the morale of mixed armies (`GRUMBLE`). `luckOf` and `moraleOf` in `rules/battle/battle.ts` are all the engine and the AI read; `spiritsOf` in `rules/heroSheet.ts` says why, for the cards.
  - Sounds: every effect is data in `src/audio/effects.ts` (how it's made, in code, and its mark and level in the mix), built from the pieces in `audio/synth.ts`. A troop's sounds in battle (its blow, cry and feet, and whether blows ring on its armour) are `TROOP_SOUNDS` in `audio/blows.ts`, and its shot is its missile in `render/units.ts`: a new troop needs its entry there, as it needs its art.
  - Battle AI (`rules/battle/ai.ts`): it tries every option with the real rules, so new content needs no AI changes.
  - Map AI (`rules/map/roaming.ts`): an enemy's `behaviour` (guard, roam, hunt), `range`, `sight`, `pace`, `bold` (hunts whatever the odds), `wakes` (holds its ground until a day, then the news says it's out) and `grows` are data. A villain's `sortie` (`rules/map/sortie.ts`) sends him out of his lair with his guard the night a story flag says he's hurt: his band hunts the hero, rides home when it can't find him, and flees home beaten, his guard straggling in after him (his walls stay as strong as ever, and a new hurt sends him out again), and his gate is barred while he's out. A `convoy` (`rules/map/convoys.ts`) keeps to a road instead: every payday a share of another band (`from`) sets out with it as its escort, it goes on along the road each night, through its own people and stopping short of the hero, and at the road's end its escort goes back (Pike's grain cart). Enemies block the walk grid where the state says they stand. What the hero sees is `rules/map/sight.ts`: land he has seen stays explored for good (`map/fog.ts`), and a band that moves in the night out of his sight is `unseen`, off the map and the minimap until he sees it again (`look` reveals the land and sees the bands in a disc, and the day's reveals all go through it; at dawn `loseSight` hides what moved out of his sight and sees round a hunter on his trail).
  - The hero screen and the army: what they say (the sheet, a stack's card, the bar's hover labels, a place's hover label) is `src/rules/heroSheet.ts`; what they change are rules actions (`wear`, `unequip`, `movePack` in `hero.ts`; `moveStack`, `dismiss` in `army.ts`), dispatched through `apply` like any card's.
- `src/game/`: screen controllers (input, riding animation, events into cards and HUD), save/load. `main.ts` only boots. The hero screen is a `Screen` of its own (`game/hero.ts`) over the map, which stands still under it. On the map the view follows Aldric as he rides, on at dawn too (once the day's card is put away), and glides to anything a card opens about out of sight; he waits beside a place he'd otherwise hide, at its door (`game/doors.ts`).
- `src/render/`: 2D pixel-art drawing into an indexed 960×540 framebuffer, with one 256-colour palette for everything (the Wesnoth units included). It reads the rules state and never changes it. The map's land is painted in tiles of 128 pixels as they come into view, trees and buildings included, and the rest a tile a frame (`terrain.ts`, `mapTiles.ts`), so a big province opens at once. The fog (`fog.ts`) never lies over a cell the hero has seen: its soft edge is on the unexplored side, and `isFogged` is exactly the unexplored cells. The day's light (`weather.ts`) falls on the land he knows and on whatever stands on it, never on the fog (the adventure screen's `veil`), which darkens at night instead. Every screen's picture is `MAP_VIEW` (`frame.ts`). On the adventure map the minimap lies over the view's top right corner (`MINIMAP`; `minimap.ts`: the land worked out once from the walk grid and `TerrainPainter.overview`, the fog laid again where the hero has seen, marks from `marksOf`, painted into its own box only when something on it changes, and laid over the map every frame after the light and the night), and the button in its corner, or Tab, folds it away.
- `src/ui/`: HTML/CSS overlays (parchment cards, hover label, the hero screen in `heroScreen.ts` with its drag and drop). They grow with the canvas (`ui/scale.ts`). A card too tall for its room scrolls its words above its buttons and says so (the cut edge fades, "more ▾" points down, and the wheel turns the words from anywhere on the card); every new card opens at its top. A battle's fallen go at the top of its card, or after the lines the rules say (`BattleResultCard.after`: on a villain's, once he's taken). Artifact and stat pictures are drawn in code in `render/artifactIcons.ts`.
- `public/assets/wesnoth/units/`: Battle for Wesnoth's unit PNGs, unchanged, from the pinned tag. `src/render/units.ts` says which unit and frames each troop uses (from its Wesnoth `.cfg`), and which figure each background's hero is (`heroArtId`); `src/render/wesnoth.ts` recolours, scales and matches them to the palette as the game runs. `npm run wesnoth` downloads missing images (`-- --palette` re-picks the palette colours the art adds, `-- --credits` rewrites `public/assets/CREDITS.md`).

## Loop

Change, run the tests, open the game in the browser panel, screenshot, fix.

- `npm run dev`: dev server on http://127.0.0.1:5188 (5173 is often taken on this machine). Scroll with arrows, WASD or drag; click to ride; E ends the day; H opens the hero screen; J the journal; Tab folds the minimap away; M mutes the sound; ? lists every key. The game opens on the title, then the King's prologue at court; `?quick=1` (or any debug start, or `?freeze=1`) goes straight to the map, and `?title=1` brings the title back when frozen. `?fresh=1` ignores the save, `?freeze=1` stops the clock (and doesn't save, and screens change without a transition; `&transitions=1` keeps them, to step through with `__kc.advance`), `?speed=8` rides faster, `?x=&y=` centres the camera, `?battle=patrol` opens that fight (`&hero=ranger` picks the background, and skips the opening card on the map, `&spells=fireball` teaches spells, `&army=knights:20,archers:30` sets the army, `&gear=twinWand,oldBanner` gives artifacts: worn if the slot is free, else in the pack), `?court=N` opens the court after commission N (`&flags=pike:false,dwarf:friend` sets story flags first, so the King has something to remember), `?commission=2` starts in the Fenmarch (3 to 5 are generated), `?chapter=N` (2 to 5, with optional `&hero=wizard&seed=1066`) has the bot play earlier commissions and courts before handing you the carried campaign, `?reveal=1` lifts the fog, `?movement=40` leaves that much of today's riding (for the evening's light; 0 is nightfall).
- `npm test`: Vitest (rules, map, movement, bot). `npm run test:fast` leaves out the bot's whole-commission runs (`npm run test:bot`, minutes long). `npm run typecheck` and `npm run build`.
- `npm run sim [-- 50]`: the bot plays the commission for many seeds, per background, and prints a balance report. `npm run sim -- 10 --campaign` plays both commissions, court included. `npm run sim:battles` prints win chances for each fight. `npm run sim:boss` prints the army each background needs to beat a villain half the time, with and without his spells and orders.
- `npm run e2e`: plays the whole commission through the real UI on its own server; exit code 1 on failure.
- `npm run visual [-- --approve]`: frozen scenes, exact frame hashes against `test/visual.json`, PNGs in `screenshots/visual/`. Scenes drawn in the page, like the hero screen (`dom: true`), hash the screenshot instead. Don't edit files while e2e or visual run: the dev server reloads the page.
- `npm run shots`: ad-hoc screenshot of the running dev server (env: `QUERY`, `RIDE=x,y`, `OUT`).
- `npm run listen [-- stings|tracks|effects|ambience|name] [--check]`: renders the sound offline in headless Edge, through the game's buses and master, and prints loudness as the ear hears it (K-weighted LUFS, against `MARKS` in `src/audio/context.ts`), peaks, how long things ring, how bright each effect is and the level that would put it on its mark, how far the score ducks under each sting and how far the sting stands over it, how loud each pass of a track's form is, its loop seam, and gated tracks in each mood. `--check` exits 1 if a track, a sting or an effect is off its mark or an effect peaks near full scale: run it after changing any sound, and set the new one's `level` from its fit. Nobody can listen to it here: measure instead. Music is data in `src/audio/score.ts` (sections, a form of passes, parts gated by the battle's mood, a `level` and a `calm` level for each track); which tune plays where is `src/game/tunes.ts`. `__kc.sound()` says what's playing, in what mood, how far the score is ducked and the ambience dipped, and the last effects asked for.
- **CI and deploys:** GitHub Actions (`.github/workflows/ci.yml`).
  - **Every pull request:** typecheck, the build and the fast unit tests (`test:fast`, the check "Typecheck, unit tests, build"); the bot's whole-commission tests (`test:bot`); and the play-through (`e2e`, in Playwright's own Chromium: `CHANNEL=bundled`) with a playtest per background.
  - **Main (on a push or a dispatch):** the same check gates the deploy to GitHub Pages (https://arturcrmbot.github.io/kings-commission/), a few minutes later. Then come the play-through and the balance report (the bot's campaign and the difficulty targets).
  - **By hand only:** the visual scenes (Run workflow > visual, on a Mac, report only). Approve baselines locally on a Mac.
  - Screenshots are the run's artifacts, and results go in its summary. If main breaks, an issue labelled `ci` opens itself, and it closes when main is green.
  - The repo is private (Pro: 3,000 Actions minutes a month, Mac minutes count 10×), so don't add jobs that run twice for one commit.
  - `gh run list`, `gh run watch`. `npm run deploy` now only prints a note saying this.
- **Merging:** the session that opened a PR merges it with `gh pr merge N --squash` once CI's three PR jobs are green ("Typecheck, unit tests, build", "The bot plays whole commissions", "Play-through and playtests"; `gh pr checks N --watch` waits for them). Main's ruleset requires those three checks for merges; admins bypass it, so wait for green, and never push to main. The merge starts CI on main, which deploys.
