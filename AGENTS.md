# AGENTS.md

Crown & Bounty is a browser game: King's Bounty (1990) rebuilt with modern tech and the charm of Heroes of Might and Magic 2, and The Old King's Treasure is its first act. Until 30 Sep 2026 it was called King's Commission (#147), and the saves' storage keys (`kings-commission/`) and the skills' folders keep that name. Read `docs/BRIEF.md` for the design and every decision made so far, `docs/PLAN.md` for the structure, testing and milestones, `docs/WORLD.md` for the story and the world, and `docs/BALANCE.md` for the power budget: what a proper challenge is, the levers, and how the sims measure it.

## Working with Artur

- Reply fast and keep it short. Before any step that will take more than a minute or two, post a one-line status. Never go silent.
- Show, don't tell. Open the game in the browser side panel and screenshot it. Use a mermaid diagram for flows.
- **The voice** (Artur, 30 Sep, #149). The game's words are plain, full sentences that speak to the player, the way HoMM2's own messages read. The narration has no colons, dashes or clipped phrases, and no put-on old-fashioned wording. Write every card to `docs/VOICE.md`, which has the rules and ten examples. Issues, PRs and messages to Artur are written the same plain way.
- Build in small, visible steps. Check in before any big build or long design deep-dive.
- No image-generation models for art. The troops and the hero are Battle for Wesnoth's units (GPL-2.0-or-later and CC BY-SA 4.0, credited file by file in `public/assets/CREDITS.md`); everything else is drawn in code. The game is GPL-2.0-or-later (`LICENSE`).
- **Build locally, from issues** (Artur, 29 Sep). An issue says what and why. A session on this Mac builds it on a branch in its own worktree and runs only the cheap checks here: `npm run typecheck`, `npm run test:fast` and the tests it touched. It looks at a few screenshots of what it changed, and runs `npm run visual -- --approve` only when it changed a frozen scene on purpose (baselines are approved here, as this is a Mac). It doesn't run `npm run e2e`, `npm run phone` or the playtest locally, because CI runs them on every PR (Artur, 30 Sep: they doubled the time of every change). Then it opens a PR that says `Fixes #N` (or `Part of #N`), and squash-merges it itself once CI's three PR jobs are green. Never push to main. The issue and its PR are the record of what was done and how.
- **Ship fast** (Artur, 28 Sep: "I want to just play this, and I'll tell you if something is not working"). Ship small slices through pull requests; the session merges its own PR once CI is green, and never pushes to main. Don't hold work back for long docs. Follow `.github/skills/kings-commission-ship/SKILL.md`.
- **Run the work** (Artur, 29 Sep, after "a ridiculously painful day"). Whoever coordinates sessions, plans a day's work or runs playtests follows `.github/skills/kings-commission-orchestrate/SKILL.md`: the finish line agreed first and kept, one local session per issue, new ideas into `later` issues, balance to one balance session, sessions watched from the start, and short messages.
- **Issues.** Bugs and features live in [GitHub Issues](https://github.com/arturcrmbot/crown-and-bounty/issues), with labels for the kind (`bug`, `feature`, `playtest`), the area (`battle`, `ai`, `content`, `ux`, `art`, `audio`, `balance`, `ci`) and the status (`in progress`, `next`, `later`, `parked`). Close issues from PRs (`Fixes #12`).
- **Models** (Artur, 29 and 30 Sep). Sessions and their helpers run on Claude Opus 5.5 with long context (`claude-opus-5.5`, `long_context`). Big features, new systems and balance run at `max` reasoning effort. Small fixes (a cursor, a font, words, a bug, a CI tweak) run at `high`, because at max they took 40 minutes instead of 10.

## Architecture

- `src/content/`: typed game data. Provinces (land, places, decor), troops, spells, backgrounds, skills, perks and artifacts.
- `src/rules/`: the game rules in plain TypeScript, with no Three.js, DOM or timers. Every change is `(state, action) → { state, events }`, and dice come from the seed in the state. The rules own the logical map (`map/`: 8 px walk grid, pathfinding, movement, fog). They write the cards' words too, and any list in them goes through `listed` in `state.ts` ("3 Knights, 2 Archers and 1 Swordsman"). Tested with Vitest.
- **Extending the game.** Most additions are data:
  - Land: a province's forests (each with its share of pines), its regions painted their own way (`fields`, `heath`, `downs`), crags, a river with a bridge wherever a road crosses it (or a ford, where `fords` says), roads and places are data in `src/content/`; `rules/map/model.ts` builds the walk grid from them and `render/terrain.ts` paints them.
  - Places: each kind of place is one module in `src/rules/places/` (a `PlaceKind`: its cards, arrival, own choices, payday, bot appetite), registered in `places/index.ts`. Towers, mines and mills show their `pages` when they have them, so a find is a choice written as content; so do castles and villages while a page holds (the old King's hunt hall, locked), and after a choice there they show their own recruit card (`PlaceKind.card`). A place that looks different once something happens to it (the hunt hall, opened) sends a `changed` event, and the map draws it anew (`refreshPlace` in `render/adventureScene.ts`). One that reads differently from afar says so in its `text.later`: the first whose `when` holds stands in for its `about` (the old delving, once the dwarf has opened it), and a save that has seen it takes the newest words (`withNewPlaces` in `rules/campaign.ts`). A pile of gold with `visit` words says what the gold was in (a pedlar's pack, the Baron's hamper) instead of vanishing silently. Aldmoor's small finds along its rides are a module of their own, `content/aldmoorFinds.ts`: keep them small, and never let one answer a quest.
  - Beasts (wild things with no wages that aren't villains: `isBeast` in `content/troops.ts`) can be tamed by a hero with `tames`: see `tameOffer` in `places/enemy.ts`. How many come over, tamed, hired or paid off in battle, is one number, the army's power (Artur, 30 Sep): `outweighs` in `content/troops.ts` gives none while his army is no stronger than theirs and all of them once it's twice as strong, and whoever doesn't come attacks at once (`ambushRest`). Troops who draw no wages (beasts, the old King's huntsmen) need no leadership. Leadership also grows by +25 in place of a skill at any level-up (`RALLY` in `rules/hero.ts`), and by 20 for 500 gold from the steward at his castle, as often as he can pay (`MUSTER` in `places/dwelling.ts`). Troops who draw no wages but aren't wild, like the old King's huntsmen, say why on their card (`unpaid`).
  - Content choices: shrines, quests, parleys and events are content. They're pages of choices with `Needs` (conditions and costs, including `flag`/`notFlag`, `seen` (a place visited) and `notSpell`) and `Effects` (gold, treasure, stats, spells, troops, flags, reveal, xp, win, a new `place`, `reinforce` another enemy, `desert` this one, `travel` by a shortcut, `recruits` at a place (free, or with no payday restock, if the content says so), `rations` for the baggage (a payday's wages each)...), interpreted by `src/rules/effects/`, with story state in `state.flags`. A flag set by one place's spoils or choice can open a choice somewhere else: that is how choices come back later. A victory can ask a question too: its spoils name a page (`spoils.page`), and the victory card offers that page's choices (the grain cart's: whose grain is it now?). A choice the hero can't take shows greyed out (`needs`), naming only what he lacks (`lacksLabel`): the wrong sort of hero hears only that, and a story need he hasn't met says the choice's quiet `hint`, if it has one ("a song you don't know yet"). One with a `when` that doesn't hold isn't there at all, so a question only appears once there's something to ask about (Old Nan's, once the hall has been seen). Gear a choice asks for (`needs.artifact`) can't be sold at the armoury while that choice is still open (`wantedAt` in `rules/hero.ts`).
  - Relics (`RELICS` in `src/content/artifacts.ts`) carry a background's trick as a `Bonus` (charge, volley, forestWalk, casts, mapSpells, bribes, hires, tames), so any hero can pick one up.
  - The bounty: each commission's villain (and each generated one's template) has his `face`, the poster's `wanted` line, his `lastWords` (said on the field as his army is beaten, in a bubble and his `voice` from `content/troops.ts`, and quoted on the card) and what comes home (`homecoming`, with a picture in `returned`). The poster's price is the hideout's `reward` (`bountyOf`); a choice that takes him for another price says `because`, and the WANTED poster comes back stamped PAID with it (`bountyCard` in `rules/heroSheet.ts`).
  - The court: what the King remembers (`memories`) and who would ride on with Aldric (`friends`) are each commission's data in `src/content/campaign.ts`, read from `state.flags` at court (`happened` in `rules/campaign.ts`: `true` for any value, anything else exactly, `false` for a flag spent). The people are `src/content/friends.ts`: each is offered as a boon, and once taken rides with him for good (`hero.friends`), his `Bonus` counted with the rest, and may bring troops into the next commission (`brings`).
  - The public game (#146): how many commissions are open to play, and who the King lets slip is next, are `LAUNCH` in `src/content/launch.ts`. At the court after the last open one, the boon is followed by the closing card (`closingCard` in `rules/campaign.ts`) instead of the next briefing: more commissions are coming, links to Artur's LinkedIn (`Card.links`, opened in a new tab) to follow him and to say what you thought, and back to the title (the `title` action), whose Continue comes back to it. The bot and the debug routes ride on past it. To open another commission, raise `LAUNCH.open` and tease the next.
  - The journal (J): the commission on its pinned poster, and the things heard on the road. What was heard is each commission's `heard` in `src/content/campaign.ts`: the words as someone said or wrote them, who, and the clues (story flags, a place `seen` or `used`) for when it was heard (a flag spent since still counts) and when it paid off, ticked. `heardOf` in `rules/campaign.ts` reads them, `journalCard` in `rules/heroSheet.ts` writes the page, and the card draws it as two pages (`Card.journal`). A new thread in the content can add its line there.
  - Sets (`SETS` in `artifacts.ts`, and each piece's `set`): every piece worn adds the set's `Bonus` (`wornSets` in `rules/hero.ts`). A piece's note says what its set does; a find says how many are worn. A new artifact's 16×16 picture goes in `src/render/artifactPictures.ts`.
  - Skills (`src/content/skills.ts`): each has three ranks, and each rank is the whole `Bonus` at that rank with its note, so Advanced and Expert add a trick to the number. Tricks that aren't battle fields are read where they happen: `offRoad` in `map/movement.ts`, `manaRide` in `stepAlong`, `shadow` in `map/roaming.ts` and `rules/dawn.ts`, `veterans` in `campaign.ts`, `volunteers`, `restock` and `rents` in `rules/dawn.ts` (paydays), `odds`, `cows` and `hiresGates` in `places/enemy.ts`. Perks (`PERKS`, same file) work the same way: `freeRecruits` in `places/dwelling.ts`, `carry` and `smells` in `rules/dawn.ts`, `interest` in `heroStats` (paid with the King's gold), `choices` in `drawOptions` and `boons` at court.
  - Battle: spells, statuses and troop abilities are data in `src/content/spells.ts` and `troops.ts`, and the battle engine reads them generically. Aldric fights too, as one troop per background (`hero` in `troops.ts`: his damage grows with his level); `heroFighter` in `rules/fight.ts` gives his numbers, and `createBattle` puts him behind the line from `BattleHero.unit`. Leaders (Aldric, villains, captains) are troops with the `leads` ability: they stand off the field (`REAR`), no blow, shot or spell can target them, they take a turn only with something to do in it, and a side is beaten when its troops (`onField`) are; `rides` lets one ride out to strike and back (`rideReach`), and `bard` gives one a bard's moves instead (pay, jeer, sing: `bribePrice`, with morale and luck per stack in `moraleOf` and `luckOf`). `battleEnd` gives the words the field and the card both use. An enemy that holds the field, when Aldric retreats or is beaten, keeps what it lost, as in HoMM2: its army is whoever of it still stands, its leader too, but never more of a troop than it brought, so the guard a villain calls to the field can make up his losses and never add to them (`holding` in `rules/fight.ts`). A lair recruits on payday from what's left, and a sortie's band and a convoy's squad go home with whoever is left of them.
  - Captains (the enemy's named lieutenants, #15) are data too: a leader troop in a band's army (`rook` in `troops.ts`), with a `face` for the band's cards, the band's `lastWords` as he's taken, and a trick that is an ability (Rook's `marks`: his shots put `marked` on their target). Any villain's band can have one. On the map a band with a leader shows him, with its main troop at his heel.
  - Luck and morale: `Bonus.luck` and `Bonus.morale` are Aldric's gifts to his side, statuses add theirs (a bard's songs and jeers), and each troop's `people` (with the pairs in `FEUDS`, `troops.ts`) lowers the morale of mixed armies (`GRUMBLE`). `luckOf` and `moraleOf` in `rules/battle/battle.ts` are all the engine and the AI read; `spiritsOf` in `rules/heroSheet.ts` says why, for the cards.
  - Sounds: every effect is data in `src/audio/effects.ts` (how it's made, in code, and its mark and level in the mix), built from the pieces in `audio/synth.ts`. A troop's sounds in battle (its blow, cry and feet, and whether blows ring on its armour) are `TROOP_SOUNDS` in `audio/blows.ts`, and its shot is its missile in `render/units.ts`: a new troop needs its entry there, as it needs its art.
  - Music (#178; Artur, 1 Oct: cute, retro, 90s MIDI tunes, made by people, no orchestra): yubatake's tunes, his MIDI files kept as they are in `public/assets/music/` and credited in `public/assets/CREDITS.md`, played on the band: General MIDI instruments cut from GeneralUser GS by `scripts/soundfont.py` (Python 3 with numpy, and ffmpeg) into `band.flac` (lossless: Artur heard a lossy pack hiss) and `band.json`, which `audio/band.ts` plays through a gentle low-pass at 10 kHz (`audio/midi.ts` reads the files). `TUNES` in `audio/score.ts` says which instrument plays each of his parts and how loud, and gates parts by the battle's mood; `TRACKS` lists the tunes that take turns in each place: on a map each plays through (twice, if it's short), and after a breath the next begins. Which place's music plays when is `src/game/tunes.ts`. A castle's card, or any screen over the map, leaves the music as it is (Artur, 1 Oct). A new tune is its file, its arrangement and its `level` from `npm run listen`; an instrument the band hasn't got needs `scripts/soundfont.py` run again.
  - What a click would do (#156): the battle's pointer (`pointerFor` in `game/battle.ts`, its pictures in `render/cursors.ts`), the stacks it would reach lit (`BattleView.lit`), and a tag beside them (`ui/tag.ts`). The tag's words and numbers are the rules' own reckoning (`forecastOf` and `aimTag` in `rules/battle/forecast.ts`: `battleAct` with `expected`, so a new ability or spell needs nothing there), and the ribbon's line reads the same forecast.
  - Juice in battle (#190): a blow holds the field still for a few frames as it lands (`holdFrames` in `render/juice.ts`, a step in the battle's queue, so Auto hurries it like everything else), shows its target white for a frame, kicks the field the way it went (`kickOf`), and pops how many fell out of the stack's own badge as its count rolls down (`render/pops.ts`), with a low thump under it (`thump:*` in `audio/blows.ts`). Gentle effects (`ui/gentle.ts`, a switch in the mix panel, on by default where the device asks for reduced motion) turn the kick, the flash and the hold down.
  - Battle AI (`rules/battle/ai.ts`): it tries every option with the real rules, so new content needs no AI changes. The moves it makes for your side (Auto, "Finish it", a fight left to the sergeants) go through `sergeantsAct`, so the result card can tell the mana they spent from what Aldric cast by hand (`manaLine` in `rules/fight.ts`).
  - The odds (#154): every card about a fight (a band's card from afar and on arrival, an ambush) leads with the sergeants' verdict in its colour (`Card.verdict`, from `verdict` and `oddsOf` in `places/enemy.ts`, which read `winChance`), and a band's hover label on the map and the minimap says the same (`placeOdds` in `rules/heroSheet.ts`). The likely cost under it (`likelyLossesLine`) is what the sergeants' wins cost, so when a defeat is likelier it says a defeat costs the whole army first (#171). The odds take simulated fights, so a worker (`game/odds.ts`) works out every band's ahead of time, off the page's thread, into the cache in `fight.ts`, and a hover or a tap never waits for them.
  - Map AI (`rules/map/roaming.ts`): an enemy's `behaviour` (guard, roam, hunt), `range`, `sight`, `pace`, `bold` (hunts whatever the odds), `wakes` (holds its ground until a day, then the news says it's out) and `grows` are data. A villain's `sortie` (`rules/map/sortie.ts`) sends him out of his lair with his guard the night a story flag says he's hurt: his band hunts the hero, rides home when it can't find him, and flees home beaten, his guard straggling in after him (his walls stay as strong as ever, and a new hurt sends him out again), and his gate is barred while he's out. A `convoy` (`rules/map/convoys.ts`) keeps to a road instead: every payday a share of another band (`from`) sets out with it as its escort, it goes on along the road each night, through its own people and stopping short of the hero, and at the road's end its escort goes back (Pike's grain cart). Enemies block the walk grid where the state says they stand. What the hero sees is `rules/map/sight.ts`: land he has seen stays explored for good (`map/fog.ts`), and a band that moves in the night out of his sight is `unseen`, off the map and the minimap until he sees it again (`look` reveals the land and sees the bands in a disc, and the day's reveals all go through it; at dawn `loseSight` hides what moved out of his sight and sees round a hunter on his trail).
  - The hero screen and the army: what they say (the sheet, a stack's card, the bar's hover labels, a place's hover label) is `src/rules/heroSheet.ts`; what they change are rules actions (`wear`, `unequip`, `movePack` in `hero.ts`; `moveStack`, `dismiss` in `army.ts`), dispatched through `apply` like any card's.
- `src/game/`: screen controllers (input, riding animation, events into cards and HUD), save/load. `main.ts` only boots. The hero screen is a `Screen` of its own (`game/hero.ts`) over the map, which stands still under it. On the map the view follows Aldric as he rides, on at dawn too (once the day's card is put away), and glides to anything a card opens about out of sight; he waits beside a place he'd otherwise hide, at its door (`game/doors.ts`). Whatever he gains rises off him (`gainsOf` in `game/gains.ts`), each kind in its own colour and with its own sound (`GAIN_LOOKS` in `game/adventure.ts`, #192): gold flies to the bar as coins (`flyCoins` in `render/effects.ts`) and its count rolls up as they land, gear rises with its picture, treasure lying in view twinkles now and then, and the book on the bar lights up when something new goes into the journal. A new kind of gain needs its entry there.
- **The visitor counter** (#157, `game/counter.ts`): GoatCounter, with no cookies, counts the page view and a few milestones, each once a visit: a new campaign, the hero chosen, the first battle won and lost, the dawns of days 5, 10 and 20, a commission won, and the closing card. The map's come from the rules' events (`milestonesIn`); a new milestone is a `count` call where it happens. Nothing personal is sent. Its script loads a second after the first frame, and only if the build has a site code (`VITE_GOATCOUNTER_CODE`), which CI gives only main's build, from the repository variable `GOATCOUNTER_CODE`: the dev server, the tests and the scripts send nothing, and `npm run e2e` checks.
- `src/render/`: 2D pixel-art drawing into an indexed 960×540 framebuffer, with one 256-colour palette for everything (the Wesnoth units included). It reads the rules state and never changes it. The map's land is painted in tiles of 128 pixels as they come into view, trees and buildings included, and the rest a tile a frame (`terrain.ts`, `mapTiles.ts`), so a big province opens at once. The fog (`fog.ts`) never lies over a cell the hero has seen: its soft edge is on the unexplored side, and `isFogged` is exactly the unexplored cells. The day's light (`weather.ts`) falls on the land he knows and on whatever stands on it, never on the fog (the adventure screen's `veil`), which darkens at night instead. Every screen's picture is `MAP_VIEW` (`frame.ts`). On the adventure map the minimap lies over the view's top right corner (`MINIMAP`; `minimap.ts`: the land worked out once from the walk grid and `TerrainPainter.overview`, the fog laid again where the hero has seen, marks from `marksOf`, painted into its own box only when something on it changes, and laid over the map every frame after the light and the night), and the button in its corner, or Tab, folds it away.
- **Aldmoor's painted map and battlefield** (#178): pieces cut from Retro Diffusion sheets by `npm run mapart`, and dressed as HoMM2 dresses its maps by `render/dressing.ts` (woods by kind, a scene round every place, the river's banks, no bare stretch), with rolling ground in `render/terrain.ts` and the battle's field in `paintedField` (`render/battleScreen.ts`). Follow `.github/skills/kings-commission-mapart/SKILL.md` for any change to how they look.
- `src/ui/`: HTML/CSS overlays (parchment cards, hover label, the hero screen in `heroScreen.ts` with its drag and drop). They grow with the canvas (`ui/scale.ts`). A card too tall for its room scrolls its words above its buttons and says so (the cut edge fades, "more ▾" points down, and the wheel turns the words from anywhere on the card); every new card opens at its top. A battle's fallen go at the top of its card, or after the lines the rules say (`BattleResultCard.after`: on a villain's, once he's taken). Artifact and stat pictures are drawn in code in `render/artifactIcons.ts`.
- **The lettering** (#148): every word, on the canvas (`render/text.ts`) and on the cards (the CSS in `src/ui/`), is set in Bounty Serif, TeX Gyre Pagella (a free Palatino) cut down to the game's letters, in `public/assets/fonts/`, so it looks the same on every device, Android phones included, which have no Palatino. `main.ts` waits for it (`loadLettering`) before anything paints a word. It keeps the Mac's Palatino's look: its line spacing, and its widths for the signs Pagella draws differently. `npm run fonts` makes it again (Python 3 with `pip3 install fonttools brotli`): add a character to `UNICODES` in `scripts/fonts.py` before the game's words use one it lacks.
- **Played by touch** (#144: a phone or tablet, `(pointer: coarse)`, or `?touch=1`), `ui/touch.ts` marks the page `kc-touch`, and every change is gated on it, so the desktop stays as it was.
  - **The rails.** The display leaves a strip down each side of the picture, and the rails (`ui/rail.ts`) put big buttons there for what keys do: each screen's `buttons()` (`game/screen.ts`), with Full screen (`ui/fullscreen.ts`; an iPhone gets a card on Add to Home Screen instead) and Sound always there.
  - **The words on the canvas.** The picture shrinks to fit a phone, so the bars, the battle's ribbon, its turn strip and the counts on the hexes draw their words 1.3 times bigger by touch (`setLettering` and `lettered` in `render/text.ts`), and a stack's line drops its last tags rather than its size. The desktop's frames stay exactly as they were.
  - **Cards and the hero screen.** Cards keep between the rails (`uiRoom` in `ui/scale.ts`). The hero screen takes the whole window instead, in one column (`.kc-hero-frame`), and scrolls.
  - **Upright,** the page shows the game's name over its painting (`TitleScreen.upright`) and a card asking for the phone on its side (`ui/turn.ts`), and the clock stands still.
  - **A finger** taps, drags the map, and held still, points, as a mouse hovers (`game/input.ts`: its label stays up until the next touch). The browser's own click after a tap is cancelled on the canvas, so a card a tap opens never takes it too. In battle a first tap shows what a second would do, in the tag beside the stack or hex (`BattleController.armed`). Words say "tap" where they'd say "click" or name a key.
- `public/assets/wesnoth/units/`: Battle for Wesnoth's unit PNGs, unchanged, from the pinned tag. `src/render/units.ts` says which unit and frames each troop uses (from its Wesnoth `.cfg`), and which figure each background's hero is (`heroArtId`); `src/render/wesnoth.ts` recolours, scales and matches them to the palette as the game runs. `npm run wesnoth` downloads missing images (`-- --palette` re-picks the palette colours the art adds, `-- --credits` rewrites `public/assets/CREDITS.md`).

## Loop

Change, run the tests, open the game in the browser panel, screenshot, fix.

- `npm run dev`: dev server on http://127.0.0.1:5188 (5173 is often taken on this machine). Scroll with arrows, WASD or drag; click to ride; E ends the day; H opens the hero screen; J the journal; Tab folds the minimap away; M mutes the sound; ? lists every key. The game opens on the title, then the King's prologue at court; `?quick=1` (or any debug start, or `?freeze=1`) goes straight to the map, and `?title=1` brings the title back when frozen. `?fresh=1` ignores the save, `?freeze=1` stops the clock (and doesn't save, and screens change without a transition; `&transitions=1` keeps them, to step through with `__kc.advance`), `?speed=8` rides faster, `?x=&y=` centres the camera, `?battle=patrol` opens that fight (`&hero=ranger` picks the background, and skips the opening card on the map, `&spells=fireball` teaches spells, `&army=knights:20,archers:30` sets the army, `&gear=twinWand,oldBanner` gives artifacts: worn if the slot is free, else in the pack), `?court=N` opens the court after commission N (`&flags=pike:false,dwarf:friend` sets story flags first, so the King has something to remember), `?commission=2` starts in the Fenmarch (3 to 5 are generated), `?chapter=N` (2 to 5, with optional `&hero=wizard&seed=1066`) has the bot play earlier commissions and courts before handing you the carried campaign, `?reveal=1` lifts the fog, `?movement=40` leaves that much of today's riding (for the evening's light; 0 is nightfall), `?touch=1` plays it as a phone would (the rails, the words), in a desktop window.
- `npm test`: Vitest (rules, map, movement, bot). `npm run test:fast` leaves out the bot's whole-commission runs (`npm run test:bot`, minutes long). `npm run typecheck` and `npm run build`.
- `npm run sim [-- 50]`: the bot plays the commission for many seeds, per background, and prints a balance report. The bot plays as a careful player would (`rules/bot.ts`): it fights only with a margin and learns the skills that multiply. `npm run sim -- 10 --campaign` plays both commissions, court included. `npm run sim:battles` prints win chances for each fight. `npm run sim:boss` prints the army each background needs to beat a villain half the time, with and without his spells and orders. `npm run sim:curve [-- 3]` prints the power curve (`docs/BALANCE.md`): the careful player's strength in Grimsbys by day, Grimsby as he stands, the day each gate falls, and Grimsby's odds on day 21 (`--bot` for the old, reckless bot, `--bg`, `--days`). `npm run difficulty` also plays the reference hero to day 21 and prints his odds at the villain's gate.
- `npm run rides [-- --png out.png]`: for each of Aldmoor's lands and along its roads, the longest ride between two things worth stopping for, and where (`rules/map/rides.ts`; the picture colours every spot a player rides by the ride to the nearest thing). Its test keeps it under a day everywhere and about half a day on the roads (#124): run it after moving, adding or taking away a place.
- `npm run linkpreview`: the link preview's picture (`public/link-preview.png`, the `og:image` in `index.html`, 1200×630), cropped from the title painting on the game's canvas. Run it after the painting or the name on it (`render/titleScreen.ts`) changes. The page's own name is in `index.html` (its title and `og:title`), and the site's address only in its `og:url` and `og:image`.
- `npm run icons`: the game's icon, a gold crown on royal blue drawn in code (`render/icon.ts`), saved as the PNGs in `public/` for the browser tab (`index.html`) and a phone's home screen (the `apple-touch-icon`, and the web-app manifest's, a maskable one included). Run it after changing the crown: a unit test checks the files match it.
- `npm run e2e`: plays the whole commission through the real UI on its own server; exit code 1 on failure.
- `npm run phone`: plays Commission I by touch alone on an emulated phone, sideways, from the title to Grimsby, the court and the closing card (its LinkedIn link tapped open): every press a real tap, drag or long press. It checks the upright card, the rails and the size of everything it taps, and screenshots every screen into `screenshots/phone/`. Default iPhone 13 landscape; `DEVICE="Pixel 7 landscape"` for an Android; `QUICK=1` stops after the hero screen. Run it after changing anything a finger touches.
- `npm run visual [-- --approve]`: frozen scenes, exact frame hashes against `test/visual.json`, PNGs in `screenshots/visual/`. Scenes drawn in the page, like the hero screen (`dom: true`), hash the screenshot instead. Don't edit files while e2e or visual run: the dev server reloads the page.
- `npm run shots`: ad-hoc screenshot of the running dev server (env: `QUERY`, `RIDE=x,y`, `OUT`).
- `npm run listen [-- stings|tracks|effects|ambience|name] [--check]`: renders the sound offline in headless Edge, through the game's buses and master, and prints loudness as the ear hears it (K-weighted LUFS, against `MARKS` in `src/audio/context.ts`), peaks, how long things ring, how bright each effect is and the level that would put it on its mark, how far the score ducks under each sting and how far the sting stands over it, how loud each quarter of a tune is, its loop seam, and gated tunes in each mood. `--check` exits 1 if a tune, a sting or an effect is off its mark or an effect peaks near full scale: run it after changing any sound, and set the new one's `level` (and a villain's lair arrangement's `calm`) from its fit. Nobody can listen to it here: measure instead. The music's arrangement is `src/audio/score.ts` (see Music, above). `__kc.sound()` says what's playing, in what mood, how far the score is ducked and the ambience dipped, and the last effects asked for.
- **CI and deploys:** GitHub Actions (`.github/workflows/ci.yml`).
  - **Every pull request:** typecheck, the build and the fast unit tests (`test:fast`, the check "Typecheck, unit tests, build"); the bot's whole-commission tests (`test:bot`), run only when the PR changes `src/rules/`, `src/content/` or the lockfile, and passing at once otherwise; and the play-through (`e2e`, in Playwright's own Chromium: `CHANNEL=bundled`) and the same by touch on a phone (`phone`). The playtest per background runs on main only, because it's a report and never fails.
  - **Main (on a push or a dispatch):** the same check gates the deploy to GitHub Pages (https://arturcrmbot.github.io/crown-and-bounty/), a few minutes later. Then come the play-through and the balance report (the bot's campaign and the difficulty targets).
  - **By hand only:** the visual scenes (Run workflow > visual, on a Mac, report only). Approve baselines locally on a Mac.
  - Screenshots are the run's artifacts, and results go in its summary. If main breaks, an issue labelled `ci` opens itself, and it closes when main is green.
  - The repo is public, so Actions minutes are free. If it's ever private again (Pro: 3,000 minutes a month, Mac minutes count 10×), watch them. Either way, don't add jobs that run twice for one commit.
  - `gh run list`, `gh run watch`. `npm run deploy` now only prints a note saying this.
- **Merging:** the session that opened a PR merges it with `gh pr merge N --squash` once CI's three PR jobs are green ("Typecheck, unit tests, build", "The bot plays whole commissions", "Play-through and playtests"; `gh pr checks N --watch` waits for them). Main's ruleset requires those three checks for merges; admins bypass it, so wait for green, and never push to main. The merge starts CI on main, which deploys.
